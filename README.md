# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файл из `migrations/0001_create_tasks.up.sql` монтируется в `docker-entrypoint-initdb.d` и применяется только при инициализации пустого data volume.

Обоснование проектных решений 
Так как ТЗ оставляло простор для проектирования, я самостоятельно реализовал следующие сценарии:

Автоматическая рекурсия (Chain of Tasks): Я спроектировал систему так, что при обновлении статуса задачи на done, UseCase-слой автоматически вычисляет дату следующего выполнения и создает новую задачу в базе. Это ключевой сценарий для медицинских процессов, где процедуры нельзя пропускать.

Логика работы Parity (Четность):
Для типа parity я заложил логику поиска ближайшего подходящего дня, начиная со следующего от baseTime. Если сегодня 15-е (нечетное), а нужна четная смена, система выберет 16-е. Это позволяет гибко планировать смены "через день".

Обработка Monthly и Specific Dates:

Для ежемесячных задач система проверяет наличие дня в текущем месяце (с защитой от дат вроде 31 февраля) и автоматически переносит задачу на следующий месяц, если в текущем даты закончились.

Для конкретных дат реализован выбор первого доступного будущего значения из списка.

Инфраструктурные решения:

Multi-stage Docker: Оптимизировал Dockerfile для разделения этапов сборки и запуска (образ весит меньше и работает быстрее).

Postgres Healthcheck: В docker-compose добавлена проверка готовности БД, чтобы Go-сервис не падал при первом запуске, пока Postgres инициализируется.

UTC Time: Все расчеты ведутся в UTC, чтобы избежать проблем с разными часовыми поясами у серверов и клиентов.
